# Supabase + Spring Boot + React Integration Guide

This guide explains how Supabase is integrated into this full-stack application. Since you are building this for learning purposes, it's important to understand what each part does and how they communicate.

## 1. Core Concepts

### What is Supabase?
Supabase is an open-source Firebase alternative. It provides:
- A PostgreSQL Database
- Authentication and Authorization
- Auto-generated APIs (though we will use our own Spring Boot backend instead)
- Realtime subscriptions and Storage

### How Our Application Works:
1. **Frontend (React)**: Handles the user interface. It uses the Supabase JavaScript library (`@supabase/supabase-js`) to allow users to sign up and log in. 
2. **Authentication Flow**: When a user logs in on the React frontend, Supabase verifies the credentials and returns a Session containing a **JWT (JSON Web Token)**.
3. **API Requests**: When the React frontend needs to read or write data (like saving a task), it sends an HTTP request to the Spring Boot backend. Crucially, it attaches the Supabase JWT in the `Authorization` header (`Bearer <token>`).
4. **Backend (Spring Boot)**: Acts as an OAuth2 Resource Server. When it receives a request, it intercepts the JWT. It checks the token's validity by verifying its signature using Supabase's public keys (JWKS). 
5. **Database (PostgreSQL)**: Spring Boot connects directly to the Supabase PostgreSQL database using standard JDBC/Hibernate, just like it would with a local database.

## 2. Setting Up Your Supabase Project

To run this project, you need to create a project in Supabase and get your credentials.

1. Go to [database.new](https://database.new/) or [supabase.com](https://supabase.com) and create a new project.
2. Once the project is created, you will need three things:
   - **Project URL**
   - **Anon Key** (Public API Key)
   - **Database Connection String** (Postgres)

## 3. Configuring the Application (Placeholders)

I have left placeholders in the code. You will need to replace them with your actual Supabase credentials.

### Step A: Configure the React Frontend
1. Open `Frontend/SupabaseLoginDemo/src/supabaseClient.js`.
2. Replace `"YOUR_SUPABASE_URL"` with your actual Project URL (e.g., `https://xyz.supabase.co`).
3. Replace `"YOUR_SUPABASE_ANON_KEY"` with your actual Anon Key.

### Step B: Configure the Spring Boot Backend
1. Open `Backend/SupabaseLoginDemo/src/main/resources/application.properties`.
2. Find the database URL: 
   `spring.datasource.url=jdbc:postgresql://db.YOUR_PROJECT.supabase.co:5432/postgres`
   Replace it with your actual connection string (found in Supabase under Project Settings -> Database -> URI). Make sure it starts with `jdbc:postgresql://`.
3. Set your database username (usually `postgres`) and the password you created when setting up the project:
   `spring.datasource.username=postgres`
   `spring.datasource.password=YOUR_DATABASE_PASSWORD`
4. Find the JWT Issuer URL:
   `spring.security.oauth2.resourceserver.jwt.issuer-uri=https://YOUR_PROJECT_ID.supabase.co/auth/v1`
   Replace `YOUR_PROJECT_ID` so the URL matches your Supabase Auth domain. This tells Spring Boot where to find the public keys to verify the JWTs.

## 4. How the Code Works (Deep Dive)

### React: `supabaseClient.js` & `Auth.jsx`
- We initialize the client using `createClient(supabaseUrl, supabaseKey)`.
- In `Auth.jsx`, we use `supabase.auth.signUp()` and `supabase.auth.signInWithPassword()`. This handles the entire authentication flow securely without our backend needing to know the user's password.

### Spring Boot: `SecurityConfig.java`
- We use `@EnableWebSecurity`.
- We configure `http.oauth2ResourceServer(oauth2 -> oauth2.jwt(...))`.
- This tells Spring Boot: "Every incoming request to `/api/**` must have a valid JWT. Validate this JWT using the issuer URL specified in `application.properties`."
- If the token is valid, Spring Boot extracts the user's ID (`sub` claim in the JWT) and allows the request.

### Spring Boot: `TaskController.java`
- When a request reaches the controller, we can get the logged-in user's ID using `@AuthenticationPrincipal Jwt jwt`.
- We use `jwt.getSubject()` to get the Supabase User ID (a UUID).
- We save the task with this `userId`. This ensures users can only see and manage their own tasks, enforcing data isolation.

## 5. Running the Application

1. **Start the Backend**: Navigate to `Backend/SupabaseLoginDemo` and run `./mvnw spring-boot:run`. It will connect to Supabase Postgres and create the `Task` table automatically (because we use `spring.jpa.hibernate.ddl-auto=update`).
2. **Start the Frontend**: Navigate to `Frontend/SupabaseLoginDemo`, run `npm install` (first time only), then `npm run dev`.
3. Open your browser to the local Vite URL (usually `http://localhost:5173`).
4. Sign up a new user, log in, and try adding a task! You can verify the data was inserted by going to the Supabase Table Editor.
